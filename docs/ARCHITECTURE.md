# Архитектура MonitorBox

Foundation: Uptime Kuma в контейнере, именованный том для постоянных данных, порт 3001 на loopback. Без Docker Socket, privileged, публичного порта и встроенных секретов.

## Целевая архитектура

Браузер → HTTPS / обратный прокси → Console и защищённый backend → адаптер мониторинга → Uptime Kuma. Доступ к движку через проверенный интерфейс; не читать и не менять внутреннюю SQLite напрямую. Секреты остаются на сервере; API не передаёт их браузеру. Поддержка интерфейса интеграции и разграничение прав подлежат отдельной проверке до выбора технологии.

Console: обзор, сервисы, инциденты, отчёты, настройки. Отдельные инженерные компоненты: Installer, Doctor, Recovery. Внешняя независимая точка мониторинга нужна для выявления полной недоступности самого хоста. Движок не разрабатывается с нуля; сохраняю атрибуцию upstream.

## Критерии приёмки Foundation

- Compose-конфигурация валидна, версия образа фиксирована.
- Контейнер запускается и HTTP-интерфейс отвечает.
- Порт опубликован только на 127.0.0.1.
- После остановки и повторного запуска данные сохраняются (ручная проверка).
- На тестовом сервисе обнаруживаются сбой и восстановление (следующий этап).

До коммерческого запуска необходимы настройка HTTPS и авторизации, контроль доступа, проверка уведомлений, резервного копирования и восстановления, обновлений и безопасности.
